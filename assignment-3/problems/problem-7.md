If contactSchema.safeParse only runs in the browser (e.g. purely inside ContactForm.tsx's onSubmit, with no server-side check), the "validation" is cosmetic, it only stops people using your actual UI.

Anyone can bypass it entirely, curl doesn't run your React component, doesn't run your client-side zod check, doesn't care that your form has required attributes or min={18} on the age input — those are all client-side and trivially skippable by anyone sending a raw HTTP request directly (or using dev tools to edit the DOM, disabling JS, or scripting a bot). Client-side validation is a UX convenience — instant feedback, no round-trip — not a security boundary.

That's exactly why our submitContactForm in app/actions.ts runs parseForm unconditionally on every call, with no way to skip it: the server is the only party that can enforce anything, because it's the only code path an attacker can't rewrite or bypass. Client-side checks are worth keeping (they make the honest 99% of users see instant field errors instead of waiting on a round-trip), but they're strictly additive — the server-side check is the one doing actual protection, and it has to re-run every single time regardless of what the client claims to have already checked.
